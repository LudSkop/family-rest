# Family Rest

Сайт сімейного ресторану з онлайн-бронюванням столів, передзамовленням страв для всієї компанії та AI-асистентом.

**Демо:** https://family-rest.vercel.app

## Можливості

- **Меню.** Фільтри за категоріями, сортування, картка страви з деталями.
- **Локації.** Список ресторанів і модалка з інформацією про кожен.
- **Бронювання столу.** Пошук вільних столів за датою, часом, кількістю гостей і локацією, підтвердження, зміна часу або кількості гостей, скасування.
- **Великі компанії (5–8 гостей).** Бронювання через запит, який персонал підтверджує або відхиляє на сторінці `/staff/requests`.
- **Запрошення.** Власник бронювання ділиться посиланням `/join/<code>`, і гості приєднуються з акаунтом або без нього.
- **Передзамовлення.** Кожен учасник збирає свій кошик і відправляє його, а власник бачить замовлення всієї компанії.
- **Акаунт.** Реєстрація з підтвердженням email кодом, вхід (зокрема через Google), відновлення пароля, «Мої бронювання».
- **AI-асистент.** Чат, який відповідає потоком (SSE) і може пропонувати дії з бронюванням, а користувач їх підтверджує.

## Як це влаштовано

Браузер не звертається до бекенда напряму. Усі запити йдуть на сервер Next.js (`/api/v1/...`), а він пересилає їх на бекенд за адресою з `API_URL`:

```
Браузер → Next.js /api/v1/*
            ├─ потоки асистента → Route Handler (fetch) → бекенд
            └─ усе інше         → fallback-rewrite      → бекенд (API_URL)
```

Шляхи на Next-сервері збігаються з бекендом один в один, тому cookie сесії працюють без змін. `API_URL` використовується лише на сервері.

### Rewrite

Майже всі запити пересилає `fallback`-rewrite у [`next.config.ts`](next.config.ts). Запит і відповідь проходять як є: статус, тіло, `Set-Cookie`, `Retry-After` і редирект `302` входу через Google.

Саме `fallback`, а не звичайний rewrite: він спрацьовує лише тоді, коли не знайшлося жодного маршруту (зокрема динамічного), тож Route Handlers асистента обробляються першими.

### Потоки асистента

Власні Route Handlers лишилися лише для двох потокових відповідей асистента (Server-Sent Events):

- `POST /assistant/sessions/:id/messages`: питання асистенту
- `POST /assistant/sessions/:id/actions/:actionId/apply`: застосувати картку дії

У них `maxDuration = 300`, щоб Vercel не обірвав потік (бекенд обмежує відповідь 240 с). Обидва викликають [`proxyStream`](app/api/_utils/proxyStream.ts):

- пересилає cookie браузера, але самі токени не читає;
- віддає потік без буферизації;
- помилку (`401`, `422`, `429`…) повертає звичайним JSON разом із `Retry-After`;
- зупиняє запит до бекенда, коли користувач закрив чат.

### Сесія

- Сесія зберігається в cookie, які ставить бекенд (`access_token`, `refresh_token`). JavaScript у браузері токенів не бачить.
- Коли запит отримує `401`, клієнт один раз оновлює сесію (`POST /auth/refresh`) і повторює запит.
- Одночасно йде лише одне оновлення, інші запити чекають на нього. Бекенд вважає повторне використання refresh-токена крадіжкою і завершує всі сесії.
- Для запитів входу й реєстрації (`/auth/login`, `/auth/register` тощо) `401` означає реальну відмову, тому там сесію не оновлюють.

## Запуск локально

Потрібні **Node.js 20.9+** і доступ до бекенда Family Rest.

```bash
# 1. Встановити залежності
npm install

# 2. Створити файл зі змінними середовища
cp .env.example .env.local
#    і вписати в .env.local адресу бекенда

# 3. Запустити
npm run dev
```

Сайт відкриється на http://localhost:3000.

## Тести

Тести лежать поруч із кодом, який перевіряють, і мають суфікс `.test.ts`:

```
lib/utils/
  formatPrice.ts
  formatPrice.test.ts
```

## Структура проєкту

```
app/                 сторінки (App Router)
  api/v1/            Route Handlers для потокових відповідей асистента
  api/_utils/        спільні функції для них (cookie, потоки)
components/          компоненти; у кожного своя папка з .tsx і .module.css
hooks/               власні хуки (поточний користувач, чат асистента…)
lib/api/             клієнт API для браузера
lib/utils/           допоміжні функції (ціна, час, пароль…)
types/               TypeScript-типи даних з бекенда
public/              картинки та інші статичні файли
```
